# Owned source artifacts for Local V4 fixture checks

The host can materialize the genuine private phase lease as an owned ordinary-text source artifact. The trusted backend opts in when constructing preparation with `sourceArtifacts: true`. The default remains the existing data-only fixture component. No HTTP, environment or model value selects this mode; the captured backend setting cannot change across awaits. This implementation enables no native worker, verifier, provider, paid Work or protected acceptance. Their existing gates stay closed.

Preparation reconstructs the complete original/reproduction, checkpoint or final Git B1 tree through the existing fixed reader. Only then does the private artifact store receive immutable source data and its original phase binding. It validates the same bounded text graph, writes a fresh owned container and reconstructs the native-file readback with the unchanged planner/B1 validator. The store exposes a frozen descriptor only after complete readback. A descriptor, copied path or digest does not register an artifact, lease or native guard.

The trusted data directory has a qualified mode0700 parent with a fresh, exclusive private instance namespace. Existing artifact contents are never adopted. Fresh containers contain a source directory and separate bounded manifest. Source files are exclusive regular files with no-follow opens, exact lengths/content hashes, single links and descriptor/path observations; sealed files use mode0444 and source directories0555. The manifest records canonical Git mode100644, exact selected tree and original phase binding. No archive, Git subprocess, external command, worker, Docker or cleanup occurs in the store.

Existing graph limits remain:200entries,128directories,16depth,240path characters,100000bytes per blob and500000serialized file-map bytes. Manifest bytes are capped at131072; descriptor metadata at8192. All operations retain the actual current-connection and original phase denial plus the existing preparation/close budget. Namespace ownership and ancestor observations cannot be refreshed from changed paths. Preparation is lazy: constructing the store touches no filesystem.

The genuine private lease retains the exact descriptor. Close checks complete owned inventory, metadata and bytes before consuming. The R4 mandatory synchronous receipt rechecks those same facts after the last caller await, inside the existing SQLite metadata transaction immediately before source output is recorded. It performs no await or native tool there. The same single expected metadata cut then advances only exact known host outputs. Financial ledger ordering, original capture/HEAD/index fields, native checkpoint/finalizer/C code and current owner/source authority remain unchanged.

Uncertain artifacts retain their evidence and cannot be reused. Failure of shared namespace ownership holds the store; a rejected descriptor or one cancelled Work does not silently create authority for another Work. No recovery/adoption, retry, refund, UNKNOWN release, source-anchor reset or old writer follows an uncertain lease.

The native qualification remains the same three ordinary modify, create/delete and reproduction cases, with additive nested-text/artifact assertions. Older native fixtures keep their original data-only mode and bytes. New negative tests use tiny in-memory data before filesystem effects. These checks prove this source component, not filesystem transactions, native resource cessation, protected custody, independent acceptance or signed delivery Proof.
