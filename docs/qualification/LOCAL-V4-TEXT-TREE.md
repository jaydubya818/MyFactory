# Pre-checkout text input, finite unit B1

This unit extends only static local V4 preparation over the accepted native preparation source `f6934e1a692f2cfaed49f806a6c28191cc36dbfd`. It validates the complete immutable input tree before checkout. It does not qualify candidate readiness, Result export/read, later native operations, independent acceptance/Proof, paid Work, production or tester activation.

`LOCAL-V4-PREPARATION.md` describes finite unit A and its historical SHA1/SHA256 identity support. B1 narrows this preparation profile to SHA1 regular text for current MyEve interoperability. Both producer classes and the old identity reader retain their bodies and broader low-level identity behavior; those primitives are not a substitute for this new service input fence. The qualified host/runtime and exclusive stable trusted repository administration preconditions from A remain required.

The preparation API still returns exactly three frozen existing dependency functions. No generic native runner, environment callback or protocol selector is exported. Its private fixed raw-object adapter uses the existing verified Git/helper/dylib runtime and sanitized environment. For each exact full SHA1 object it first checks native `cat-file -t` and `-s` metadata. Actual type must equal the internal requested commit/tree/blob type, and canonical decimal size must fit the fixed bound before body acquisition. Specifying a Git type can dereference another type, so type metadata is checked explicitly. Raw content is acquired without pretty-print, filter, textconv, mailmap or revision/path conversion. Each new native observation retains the owned-group close/exit0/observed-absence requirement, with bounded output/deadline. No shell, remote fetch, submodule update or caller-selected native operation is added.

The pure validator accepts only bounded typed data through that trusted private reader. It detaches raw buffers and verifies the actual SHA1 of `type SPACE byteLength NUL bytes` before decoding or walking content. A unique commit root tree, canonical raw tree framing/order, distinct regular names/modes, complete object graph and independently reconstructed full file-map root must agree. Hidden empty directories, omitted paths or returned tree IDs alone cannot qualify the input. Work/spend/original-admission authority still belongs to existing canonical callers.

The fixed input profile requires:

- SHA1;1..200 regular100644 files, maximum100000 bytes/file and500000 canonical UTF8 JSON map bytes.
- ASCII paths matching letters/digits/underscore/dot/slash/hyphen, maximum240 characters; no empty/dot/dotdot segments or any ASCII case spelling of `.git`.
- No distinct ASCII-folded file or directory-prefix aliases. Spelling is compared, never rewritten.
- Exact top-level `__proto__` is unsupported until a separately qualified lossless consumer correction. Current MyEve GitHub snapshot assignment drops that ordinary filename. This is a data-loss compatibility limit, not a prototype mutation or code-execution claim. A nested full key such as `src/__proto__` remains ordinary data.
- Strict lossless UTF8, BOM preserved, no NUL. Repeated blobs count at every logical path. Canonical JSON escaped path/value/punctuation bytes are counted incrementally before collecting an oversized aggregate.
- Maximum16 path segments,128 directories including root,200 logical tree entries,65536 bytes per raw tree/commit,524288 aggregate raw tree bytes and256 native metadata bytes.

One pending exact(repository,input) observation has a single monotonic30000ms processing budget across initial resolution and the complete pre-checkout recheck/create phase. A repeated pending resolve keeps the same observation/deadline. It is consumed once only after successful exact workspace creation; a later independently admitted canonical Work may establish a fresh observation. The helper signatures carry no WorkID and grant no new authority. Existing intake replay skips preparation and cannot acquire a fresh financial or writer claim through bookkeeping.

The budget is checked around old synchronous qualification and every new observation. New commands honor remaining budget and A's bounded failure settlement; no later read/checkout starts after expiry. A's old synchronous reader retains prior per-call bounds and cannot be hard-preempted or called newly group-qualified. No hard30000ms end-to-end API latency is claimed. Failure/expiry/uncertainty quarantines the repository/helper and retains original preparation failure/HOLD. No automatic retry, history reset or crash ownership reconstruction is added. Capture-entered physical cleanup remains held under A; clean pre-capture cleanup remains separately scoped.
